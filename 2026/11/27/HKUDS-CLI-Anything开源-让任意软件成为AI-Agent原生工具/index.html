HKUDS CLI-Anything 开源：让任意软件成为 AI Agent 的原生工具

发表于2026-11-27|更新于2026-11-27|Tech前沿
|浏览量:

今天的软件，是为人类设计的；明天的用户，大概率不是人。香港大学数据科学实验室（HKUDS）开源的 CLI-Anything，正是围绕这一判断给出的一个工程化回应：用一条命令，把任意有代码库的软件自动翻译成 AI 智能体可调用的结构化 CLI。项目开源仅数月，GitHub 星标已突破 6.5 万，单日增长超过千星，是目前「让软件适配 Agent」方向最热门的开源项目之一。

为什么这件事重要

智能体要操作现实世界的工具，有几条路：截屏猜坐标、RPA 模拟点击、依赖官方 API——三条都很痛。无论是 GIMP、Blender 还是 LibreOffice，它们的 GUI 是为像素级精修设计的，对于需要稳定、可组合、可发现能力的 Agent 来说，都是不可靠的接口。

CLI-Anything 抓住的事实是：对 Agent 而言，最稳定的接口不是 GUI，也不是每家不一样的私有 API，而是结构化 CLI。如果把每个软件都包一层 CLI，智能体就能像调用内置工具一样调用这些软件——既能发现它们的能力，也能以 JSON 输出稳定地接收结果。

全自动 7 阶段流水线

项目的核心资产不是「某一个 CLI」，而是一套 agent-harness 方法论。它提供一个全自动 7 阶段流水线：分析目标软件的代码库，生成结构化命令、参数约定和 JSON 输出 schema，再用测试验证每一条命令。结果是「把 GIMP、Blender、LibreOffice 之类的专业软件，交付成生产级 Agent 工具」。

截至目前，项目已覆盖 18 款专业软件，并附带 1,774 项测试全部通过。整个系统还提供 CLI-Hub 包管理器，社区可以共享和复用这些生成的 CLI 接口，而不是每个人重写一遍。

与 GUI、API 的差别

维度 GUI 截屏/点击 私有 REST API CLI-Anything
稳定性 低（脆弱的坐标/行为） 中（覆盖不全） 高（结构化命令 + JSON）
Agent 可发现性 无 弱 强（自描述接口）
组合性 差 差 好（可链式调用）

关键在于 CLI 的自描述性：Agent 读取命令帮助时就能得到完整的参数和返回结构描述，运行时也以 JSON 输出，便于后续管线继续处理——这是截图和模拟点击无法提供的能力。

意义与展望

这件事的影响并不只是「让 AI 学会用 GIMP」。它的示范意义在于：软件即将进入一个「Agent 优先」的时代。今天人们在讨论 MCP、Skills、AGENTS.md，这些都是 Agent 生态的规范层；CLI-Anything 则补上了一层更底层的能力——无论你的软件是否为 Agent 设计，它都有可能被自动包装成 Agent 原生工具。

自然也存在争议：生成的 CLIs 质量依赖于源软件的代码可维护性，测试覆盖面能否持续扩张，以及 Apache-2.0 许可之下社区共享 CLI 的治理边界，都是值得观察的问题。但无论如何，这个方向已经被行业确认为基本盘之一。

总结

  • CLI-Anything（HKUDS，Apache-2.0）：一条命令把任意软件自动转为结构化 CLI，Agent 可直接调用。
  • 核心资产是 7 阶段全自动流水线 + CLI-Hub 包管理器，覆盖 GIMP、Blender、LibreOffice 等 18 款专业软件。
  • 与截图/点击/私有 API 相比，结构化 CLI 是最适合 Agent 的接口形态。
  • 博客读者从今天起就可以「给软件穿上结构化接口」——如果你手里有一款自己常用的工具，CLI-Anything 可能正好是让它 Agent-Native 的那一把钥匙。
